# Comfy豆包通用生图（astrbot_plugin_comfy_ark）

> 插件仓库：<https://github.com/yydsmb/astrbot_plugin_comfy_ark>

> **v3.0.0 起更名**：插件标识从 `astrbot_plugin_doubao_image` 改为 `astrbot_plugin_comfy_ark`，LLM 工具名从 `doubao_generate_image` 改为 `comfy_ark_generate_image`。
> 升级时把配置文件 `data/config/astrbot_plugin_doubao_image_config.json` 复制成 `astrbot_plugin_comfy_ark_config.json` 即可（插件目录里的 `refs/` 与 `workflows/` 原样保留）。

AstrBot 生图插件，**本地 ComfyUI 优先、云端火山方舟（豆包 / Doubao Seedream）兜底**，支持**文生图**与**图生图**。

> 云端接口：`POST https://ark.cn-beijing.volces.com/api/v3/images/generations`（`Authorization: Bearer <API Key>`）
> 本地接口：`POST http://127.0.0.1:8188/prompt`（ComfyUI HTTP API，无需鉴权、不花钱、不需要 Key）

三档后端由 `backend` 决定：

| `backend` | 行为 | 需要 api_key |
| --- | --- | --- |
| `local_first`（默认） | 先跑本地 ComfyUI；本地失败（连不上 / 超时 / 工作流报错）自动转云端 | 建议填（兜底要用） |
| `local_only` | 只用本地，一次都不碰云端 | 不需要 |
| `cloud_only` | 只用云端（= v1.x 的老行为） | 必填 |

**v2.0.0 的三块新能力**：本地 ComfyUI 后端、**内容审查**（本地出图没有上游审核，必须自己挡）、
**人格参考图**（图片放插件目录、以人格名命名，AI 自己决定用不用）。详见下文各自的小节。

## 核心特点：参考图可有可无，用户自己选

| 你想做的事 | 怎么做 |
| --- | --- |
| 只要一张全新的图 | `/画图 一只戴墨镜的橘猫坐在海边看日落` |
| 拿一张图改风格 / 换背景 | 图 + `/画图 把背景换成赛博朋克城市夜景`（图与指令同一条消息） |
| 图在别人发的消息里 | **引用**那条消息（或回复它），再发 `/画图 换成油画风格` |
| 图在网上 | 直接把图片链接写进提示词：`/画图 把这个链接的图变成水彩：https://xxx/a.png` |
| 消息里带了图，但我这次只想文生图 | 用 `/文生图 <提示词>`（忽略附图） |
| 我一定要用参考图 | 用 `/图生图 <提示词>`（没检测到参考图会提示） |
| 让 AI 用**它自己**的形象来画 | 把图放进插件目录的 `refs/`，文件名 = 人格名（例如 `橙橘.png`），然后说「画你自己」 |
| 这次一张参考图都不要 | `/文生图 <提示词>`，或直接说「别参考任何图」 |

不带参考图、带参考图，两条路都通 —— **由用户当次决定，AI 也可以自己挑**。

参考图有两个来源：

| 来源 | 放哪儿 / 怎么给 | 谁在用 |
| --- | --- | --- |
| **人格参考图** | 用户提前放在插件目录的 `refs/`，文件名 = AI 人格名 | 本地「参考图工作流」，也可给云端 |
| **消息附图** | 图片与指令同一条消息 / 引用带图的消息 / 提示词里写图链 | 本地与云端都行 |

两条路可以任选其一，也可以都不用；拿不准时 AI 会按 `reference_priority` 自动挑。
发 `/画图参考` 能直接看到目录现状和哪个人格还没图。

## 指令

| 指令 | 说明 |
| --- | --- |
| `/画图 [提示词]` | 自动：消息里有图 → 图生图；没有 → 文生图 |
| `/生图 [提示词]` | 同 `/画图` |
| `/图生图 [提示词]` | 强制图生图，必须提供参考图 |
| `/文生图 <提示词>` | 强制文生图，忽略消息中的图片 |
| `/画图诊断` | **零成本自检**：后端 / 本地 ComfyUI 连通性与工作流节点 / 审查配置 / 云端 Key·欠费·模型开通·单价 |
| `/画图审查` | 看内容审查的当前配置，以及所有可用的 Provider ID（挑识图模型用） |
| `/画图参考` | 看人格参考图目录现状：有哪些图、哪个人格还没图、当前会话用的是哪个人格 |
| `/画图帮助` | 查看后端、模型、审查、费用与用法 |

另外插件注册了 LLM 工具 `comfy_ark_generate_image`：直接在对话里说「画一只猫」「发张图给我」「把这张图改成动漫风」「画你自己」，AI 会自己调用本插件并**把图直接发出来**。

AI 调用时可以自己决定参考图从哪来 —— 工具参数 `reference_source` 有四个取值：

| 取值 | 含义 | 什么时候 AI 会这么选 |
| --- | --- | --- |
| `auto`（默认） | 按 `reference_priority` 自动挑 | 用户没明说、又带了图 |
| `persona` | 只用当前人格的参考图 | 用户说「画你自己 / 用你的形象」 |
| `message` | 只用消息里带的图 | 用户说「照着这张图改」 |
| `none` | 完全不用参考图 | 用户说「别参考任何图」 |

> 提示词可以带空格：指令参数用的是 `GreedyStr`，`/画图 一只 戴墨镜的 橘猫` 会完整收下整句，
> 不会被截断成「一只」。

## 想用 5.0-lite（或遇到「模型选了却生不出来」）

2026-09-15 用**零成本探针**（只带 `model`、不带 `prompt`，请求停在参数校验就失败，
不生成图片、不产生任何费用）把「模型 ID × 接入点」矩阵扫了一遍，结论是：

| 现象 | 含义 |
| --- | --- |
| 标准端点返回 `400 MissingParameter` | 模型 ID 是**合法的**（不是拼写错误） |
| 标准端点真发请求返回 `400 InvalidParameter: unable to decode '' as int64` | **别名 → 接入点解析拿到空值**：本账号下**没有可用接入点**，即该模型**未开通**；与参数 / Key / 余额无关 |

所以本插件对这类情况的处理是「**说清根因 + 给两条出路 + 自动兜底**」：

1. **开通（推荐）**：到火山方舟控制台 **「系统管理 → 开通管理 → 视觉模型」** 开通
   `Seedream 5.0 lite`（送 50 张免费额度）。开通后立即生效，插件不用改任何配置。
2. **CodePlan / Agent Plan**：`lite` 与 `pro` 在 plan 端点上会走到鉴权（返回 401），
   说明它们属于 Agent Plan 模型族。若你持有 CodePlan，把 `api_url` 换成
   `https://ark.cn-beijing.volces.com/api/plan/v3/images/generations`，
   `api_key` 换成 plan 专属 Key，模型名用点号写法 `doubao-seedream-5.0-lite` 即可。
3. **自动兜底（`auto_fallback`，默认开）**：未开通期间，插件检测到这类路由错误会
   **自动改用 `fallback_model`（默认 4.0）重新生成一次**，并在结果里注明实际用的模型。
   失败请求不计费，所以这一步不多花一分钱，但能保证你永远不空手而归。

启动日志、`/画图诊断`、报错文案三处都会给出同样的开通指引，不用再猜。

## 出问题先发 `/画图诊断`

`/画图诊断` 覆盖四段：**本地 ComfyUI**（连通性 / 版本 / 显存 / 队列 / 两个工作流的节点齐不齐）、
**内容审查**（开关、识图模型、失效策略）、**可用对话模型**（可当识图模型的 Provider ID 列表）、
**云端账户**（下面这段）。

云端那一段用一个**零成本**请求（故意不带 `prompt`，只走到参数校验就失败，不会生成图片）
把下面这些一次分清：

| 现象 | 真实原因 |
| --- | --- |
| `HTTP 403 / AccountOverdueError` | **账户欠费**，充值即可（不是 Key 也不是模型的问题） |
| `HTTP 403 / Forbidden` | 多为该模型未在本账号开通 |
| `HTTP 401 / AuthenticationError` | API Key 无效或格式错误 |
| `HTTP 404 / InvalidEndpointOrModel` | 模型 ID 不存在 / 未开通 |
| `HTTP 400 / MissingParameter` | 正常（说明 Key、模型、账户都没问题） |

诊断还会额外做一次 **plan 端点探测**（同样零成本）来判断该模型属于哪条通道：
返回 `401` → 属于 Agent Plan 模型族；返回 `404 UnsupportedModel` → 只能走标准端点。

> 特别提醒：**403 不等于「没权限」**。方舟对欠费账号返回的正是
> `403 + type=Forbidden + code=AccountOverdueError`，和权限问题长得一模一样，
> 插件会优先按上游原文识别欠费，并在报错里保留原始 `code` 与上游原文，方便你自己核对。

## 参考图是怎么处理的

火山方舟的 `image` 参数既接受 **http 链接**也接受 **base64**。但 QQ / 微信下发的图片链接通常带鉴权，方舟服务器抓不到，所以插件默认：

1. 先把参考图**下载到本地**（已经是本地文件 / base64 的直接用）；
2. 用**魔数**校验它确实是图片（jpg / png / webp / gif / bmp / tiff / heic / avif），不是就跳过；
3. 超过体积上限（默认 8MB）的跳过；
4. 编码成 `data:image/xxx;base64,...` 提交。

如果你的图是公开可访问的图床链接，可以把 `reference_transport` 改成 `url` 走直链、更省流量。

参考图最多用几张由 `max_reference_images` 决定（默认 4，硬上限 10）。

## 本地 ComfyUI 后端（v2.0.0）

默认走 `http://127.0.0.1:8188`，可以在 Comfy Desktop、命令行版或另一台机器上跑。
插件不依赖 websocket，走的是官方 HTTP API：

```
POST /upload/image   ← 有参考图时先把图传进 ComfyUI 的 input 目录
POST /prompt         ← 提交工作流，拿 prompt_id
GET  /history/{id}   ← 轮询直到完成（默认每 3 秒一次）
GET  /view?filename=..&subfolder=..&type=output   ← 取图
```

### 工作流怎么给

两个位置，都留空就用插件自带的：

| 配置 | 留空时用的 | 用途 |
| --- | --- | --- |
| `comfyui_t2i_workflow` | `workflows/qwen_t2i.json` | 纯文生图 |
| `comfyui_ref_workflow` | `workflows/qwen_ref.json` | 带参考图的图生图 |

自带的两份来自 `Qwen Image 2.1` 工作流，**必须是 ComfyUI「导出（API）」出来的 JSON** ——
顶层形如 `{"1": {"inputs": {...}, "class_type": "..."}}`。
带 `nodes` / `links` / `last_node_id` 的 UI 格式插件读不了（会明确报错告诉你）。

### 为什么换工作流不用改配置

插件**不写死节点 ID**，而是按连线关系反推：

- `KSampler` 的 `positive` / `negative` 输入指向哪个节点，那里就是正 / 负面文本节点；
- `KSampler` 的 `latent_image` 指向 `EmptyLatentImage` → 说明尺寸由 `width`/`height` 决定，插件注入配置里的宽高；
  指向文本编码器的 latent 输出 → 说明**按参考图尺寸出图**，这时不注入宽高（`tst-API.json` 就是这种）；
- `LoadImage` 节点 + 文本编码器上 `images.image_N` 形式的输入 → 该工作流支持参考图。

所以从 4 号节点换成 6 号节点、从 `SaveImage` 换成 `SaveImageAdvanced`，都不用改任何配置。
`/画图诊断` 里的「本地 ComfyUI」段落会把识别结果直接打出来：

```
✅ 文生图工作流：qwen_t2i.json
   采样器=6｜文本节点=4(prompt)｜负面字段=4(negative_prompt)｜尺寸节点=5(widthxheight)｜参考图=不支持
✅ 参考图工作流：qwen_ref.json
   采样器=7｜文本节点=6(prompt)｜负面字段=6(negative_prompt)｜尺寸=按参考图｜参考图=节点4
```

### 参考图工作流失败会自动退回纯文本（`comfyui_ref_fallback_text`）

这是刻意做的：参考图工作流最常见的两种失败是

1. **工作流被改动过、连线类型对不上** —— 上游返回
   `400 prompt_outputs_failed_validation`，`node_errors` 里写明
   `return_type_mismatch`（实测把 `LoadImage` 删掉、把 latent 直连到模型就会这样）；
2. **本机没装该自定义节点**。

这两种情况下插件不会把上游那句看不懂的英文甩给用户，而是**改用纯文生图工作流重跑一张**，
并在图片下方注明「参考图工作流报错，已改用纯文本重新生成 —— 本次没有用参考图」，
把真实原因附在后面。把这个配置关掉就会改成直接报错。

> 实测耗时（本机 RTX 5070 Laptop 8GB）：文生图约 **1.6 秒**（模型已在显存里）；
> 参考图工作流约 **39 秒**（首次要加载模型，可能到 1~2 分钟）。所以 `comfyui_timeout` 默认给了 600 秒。

## 内容审查（v2.0.0）

**本地出图没有上游审核** —— 云端那条路火山方舟自己会拦，ComfyUI 不会。
所以插件加了一道自己的审查，分两步：

| 步骤 | 配置开关 | 做什么 |
| --- | --- | --- |
| 生成前 | `moderation_check_prompt` | 把提示词交给审查模型，判断是否属于 R18 类别 |
| 生成后 | `moderation_check_image` | 把出图交给审查模型（**需要模型支持图片输入**），命中就拦截不发 |

任一步命中 **R18 就直接拦截、不发图**，回执里写明命中的类别与理由。

判定覆盖五类：色情或裸露 / 性化未成年人 / 极端血腥暴力 / 违禁内容 / 其它违法。
提示词里同时写明了**不构成 R18 的常规情况**（泳装、艺术人体、卡通夸张造型等），
避免把正常插画误杀。

### 识图模型怎么选

填 `moderation_provider_id`，值是 AstrBot「服务提供商」里的 **Provider ID**。
**发 `/画图审查` 会直接把可用列表列出来**，抄一个填进去即可。留空表示用当前会话的默认对话模型。

> ⚠️ 必须选一个**支持图片输入**的多模态模型，否则「生成后查图片」那一步会失败。
> 纯文本模型会在那一刻报错，插件按「审查失败」处理（默认放行）。

### 拿不准 / 审不了怎么办

两个配置把边界行为说清楚，默认都偏「可用性优先」：

| 配置 | 默认 | 含义 |
| --- | --- | --- |
| `moderation_strict` | `false` | 模型**明确说拿不准**时：`false` 按安全放行 / `true` 按不安全拦截 |
| `moderation_fail_open` | `true` | 审查**调不通**（网络错误 / 模型不支持图片 / 返回看不懂）时：`true` 放行 / `false` 拦截 |

默认放行是为了避免「审查模型一挂、生图功能整个不可用」。对合规要求更严就都改成拦截方向。

> 实现细节：判定解析支持三种返回形态（严格三行格式 / JSON / 裸关键词），
> 并且会**先剔除否定结构**再扫关键词 ——「这张图很安全，没有裸露内容」不会被误判成 UNSAFE。
> 严格格式与关键词扫描给出矛盾结论时，**保守取「不安全」**。

## 人格参考图（v2.0.0）

用户提前把图放进插件目录的 `refs/` 子文件夹（可用 `reference_dir` 改成别的路径），
**文件名（不含扩展名）= AI 人格名**：

> ⚠️ **`refs/` 位于插件目录内，用插件市场「更新 / 重装」时可能被覆盖 —— 请自己留一份备份。**
> 想彻底避开这个风险，就把 `reference_dir` 指到插件目录之外（例如 AstrBot 的 `data/` 下），
> 那里的文件不会被插件更新动到。

```
astrbot_plugin_comfy_ark/
└── refs/
    ├── 橙橘.png        ← 人格「橙橘」的参考图
    ├── 小深.webp
    └── orange.jpg
```

取图优先级：

1. 配置 `reference_alias_map` 里的显式映射（一行一条 `人格名=文件名`，也容忍 `＝` `:` `：`）
2. 文件名与人格名**完全相同**
3. **宽松比对** —— 忽略空格、下划线、连字符，所以 `小 深` 和 `小深` 本来就能对上

人格名的来源顺序（v2.0.1 起与 AstrBot 官方口径对齐）：**`persona_manager.resolve_selected_persona`
（含 umo 级会话规则、会话人格、默认人格）→ 会话表里的 `persona_id` → 默认人格 → 配置
`persona_name_default`**。占位值 `default` / `[%None]` / `_chatui_default_` 一律跳过。

> 为什么要跟官方对齐：插件是拿这个名字去**匹配文件名**的。如果它跟 AstrBot 实际喂给 LLM 的
> 那个人格不是同一个，就会出现「AI 明明叫某某，插件却按另一个名字找图 → 永远只出文生图」
> 这种看不出原因的怪事。

取不到人格名时插件不会随便抓一张图，而是明确告诉用户「没找到对应文件，请把图放进 X 目录」。

同一张图有多个格式（`橙橘.png` 和 `橙橘.jpg`）时按 `png > webp > jpg > jpeg > bmp > gif > avif` 取。

### 明明放了图，却始终只出文生图？先发 `/画图参考`

参考图靠「人格名 == 文件名」硬匹配，对不上就退成纯文生图。v2.0.0 时这一步是**静默**的，
看起来就像「插件只会文生图」。v2.0.1 起这件事会被明确说出来：

- 每次生成都留一条日志决策行：
  `参考图决策：source=auto｜人格=ai4｜人格图=不用｜消息图=0 张｜最终=文生图`；
- 自动模式下没匹配到图时，**回执里会带 ⚠️**：写明解析到的人格名、目录里现有哪些图，
  并给出可以照做的两条修法；
- `/画图参考` 会打印人格解析全过程（会话 `persona_id` / 平台 / 默认人格 / 最终采用的名字），
  并对目录里的文件算相似度，点出**名字最接近的候选**；
- `/画图诊断` 里同样多了这一整段。

最常见的三种「对不上」：

| 现象 | 原因 | 修法 |
| --- | --- | --- |
| 目录里有 `Aliya.jpg`，插件说当前人格是 `ai4` | 文件名跟**实际生效的人格名**不一致 | 把文件改名成 `ai4.jpg`，或在 `reference_alias_map` 写一行 `ai4=Aliya.jpg` |
| 提示没解析出人格名 | 会话没绑人格，也没有默认人格 | 设一个人格为默认，或填 `persona_name_default` |
| 明明在本群换成某人的人格了，插件还是按默认人格找 | 会话表里没写 `persona_id` | 官方解析优先，本不该发生；实在对不上就看 `/画图参考` 打印的四个字段 |

改文件名**立即生效**（目录 mtime 变了就重扫索引）；改 `reference_alias_map` 需要重载插件。

> 传给**本地** ComfyUI 的参考图会先经 `POST /upload/image` 上传到 ComfyUI 的 `input` 目录，
> 再把返回的文件名填进 `LoadImage` 节点。
> ⚠️ 取图那一步必须对 `filename` 做 URL 编码 —— 工作流的 `filename_prefix` 是中文
> （`Qwen_2.1-文生图`），不编码会直接抛 `UnicodeEncodeError: 'ascii' codec can't encode characters`。

## AI 自己写错参数名？插件兜得住（v2.0.2）

工具接口的契约是**插件**的事，不该让每个角色的人格提示词去手工声明一遍
（人格一多、模型一换，这个坑就会反复出现）。但模型确实会自己发明参数名 ——
实测日志里抓到过：

```
comfy_ark_generate_image 收到参数 {'use_reference_image': False}
```

插件契约里只有 `reference_source`。这属于最隐蔽的一类失败：如果模型编出来的名字
**恰好曾经存在过**，连报错都没有，功能就静默降级了（参考图永远不生效、每次都出
文生图），而用户与插件都不发一言。

所以 v2.0.2 在工具入口加了一层**参数容错**：

| 模型写的东西 | 插件怎么理解 |
| --- | --- |
| `reference_source: "persona"` | 规范写法，直接用，不产生任何噪音 |
| `use_reference_image: True` / `use_ref: True` / `with_reference: True` | 当成 `reference_source: "auto"` |
| `use_reference_image: False` / `ref_mode: "off"` | 当成 `reference_source: "none"` |
| `reference: "persona"` / `reference-source: "selfie"` / `source: "你自己"` | 当成 `reference_source: "persona"` |
| 同时写了规范名和别名 | 规范名赢，别名的存在被点出来 |
| 认不出的取值（`"banana"`） | 退回 `auto`，并说明这个取值认不出来 |
| 完全不认识的参数名（`prompt_style`） | 忽略，但**记日志 + 回执 + 回灌给模型** |

认得的别名（大小写、下划线、连字符、空格均不敏感）：

```
reference_source · ref_source · reference · ref · source
reference_image · reference_images · reference_type · reference_mode · ref_mode
use_reference_image · use_reference · use_ref_image · use_ref · use_image_reference
with_reference_image · with_reference · with_ref
use_persona_reference · use_persona_image · use_personality_reference
persona_reference · persona_image · persona_ref
image_reference · image_ref · img_reference · img_ref
```

取值也做归一化：布尔与数字按真值映射（`True` → `auto`，`False` → `none`）；
字符串除了四个规范值，还认 `selfie` / `self` / `你自己` / `人格图` / `立绘` / `引用图`
这类写法（精确查表失败后按关键词回退）。

> 为什么 `True` 映射成 `auto` 而不是直接钉成 `persona`：布尔只表达「允许用参考图」，
> 而 `auto` 会按配置的 `reference_priority` 去挑，尊重用户的偏好。默认配置
> （`persona` 优先）下，`auto` 的最终结果就是人格参考图。

对外契约也收窄了：`use_reference_image` 已从工具 schema 里**移除**
（旧版遗留的布尔开关，正是它诱导模型写出 `False` 的那个坑），工具 description
开头第一句就是「控制参考图的参数**只有** `reference_source`」。

## 提示词层：怎么让 AI 自己选对参考图（v2.0.3）

v2.0.0 解决「插件收得到参考图」，v2.0.1 解决「插件找得到参考图」，v2.0.2 解决
「插件认得出手滑写错的参数名」。最后一段留在**模型那头**：它得自己想用参考图。

实测它不用，原因有两个，都不是「模型笨」：

1. **它不知道当前人格是谁、有没有参考图。** 选 `persona` 有失败风险（万一没图），
   于是保守地选 `none` —— 在信息不足的前提下这是合理反应。而用户看到的现象就是
   「怎么画都只出文生图」。
2. **一份指令喂两个后端要写两版。** 本地 Qwen 认 `<image1>` 槽位，云端 Seedream
   不认；让模型写两版，必然出现「换后端忘了改提示词」。

### 拆两处，各放该放的东西

| 放哪儿 | 放什么 | 为什么 |
| --- | --- | --- |
| `system_prompt`（注入） | 决策规则 + **两个实时事实**（当前生效人格是谁、有没有参考图） | 短、硬、每条相关消息都在眼前 |
| 工具说明 | 写 prompt 的固定模板、变量规则、3 个 few-shot 示例、槽位约定 | 模型要调用时必然看到，又不挤占人格提示词的注意力 |

注入的那一段约 550 字，长这样（`当前事实` 那行是动态的）：

```
【生图前自查 · 调用 comfy_ark_generate_image 前必须执行】
当前事实：生效人格「Aliya」，已有人格参考图 Aliya.jpg。
一、判断 reference_source
· 画面主体是「你 / AI / 当前人格」（自己、自拍、全身、半身、立绘、换装、
  再拍一张、换个姿势、你现在的样子）→ "persona"
· 用户带了图，要求照着改 → "message"
· 画面里没有你、也没给图 → "none"
· 同时出现「画你」和「用户图」→ 主体优先，选 "persona"，用户图作为换装/背景来源
· 拿不准 → 不传参数，插件 auto
...
```

注入只在「本轮对话能用到生图工具」时发生，并做了幂等（靠 `【生图前自查` 标记串，
多轮请求不会叠好几遍）；解析人格与参考图带 30 秒缓存，不会每条消息去查库。

### 四个会导致图生图翻车的漏洞

| 漏洞 | 现象 | v2.0.3 的定义 |
| --- | --- | --- |
| **换装没处理** | 说「画你穿白衬衫」，模型顺手把脸也重写一遍 → 脸不像了 | 换装时**只**描述服装；脸和发型由「与 `<image1>` 完全一致」锁死。AI 可自主判断该不该换（洗澡、睡觉、出舱、节日、剧情需要） |
| **构图没处理** | 用户要全身照，出半身 | 构图是四个可替换变量之一，取值固定为 全身照 / 半身照 / 自拍 / 特写 / 头像 |
| **变量污染没定义** | 模型把用户原话整段塞进 `{新场景}`，或写「她是一个……的女孩」→ 长相被文字覆盖 | 明确禁止：变量只填纯场景 / 纯动作 / 纯服装；`{新场景}` 只写地点，`{新动作}` 只写动作 |
| **多图优先级不清晰** | 同时有「画你」和用户附图，模型不知道该听谁 | 主体优先：选 `persona`，用户图作换装/背景来源。序号超出的引用（悬空）由插件按句删掉 |

### 写 prompt 的固定模板

模型被要求照抄这个骨架，只换 `{变量}`：

```
保持 <image1> 里的人物身份完全不变，脸型和发型与 <image1> 完全一致。
她现在{新场景}，{新动作}，{构图}。
服装：{服装描述，可保留原服装，也可换成新服装}。
不要用文字描述或重绘她的脸、眼睛、发色、五官。
二次元赛璐璐风格，自然光线，高质量。
```

模板里同时给了**三个示例**（不换装的咖啡店自拍 / AI 自主换装的浴室 / 用户指定换装
的樱花树下），都是 few-shot，模型照着填比照着规则写稳得多。

### 双后端槽位：AI 只写 `<imageN>`，插件负责翻译

```
AI 写的 prompt          →  本地 Qwen 后端      云端 Seedream 后端
保持 <image1> 的脸型一致  保持 <image1> 的脸型一致  保持上传的参考图的脸型一致
```

* **本地**：`<image1>` / `<image2>` 原样保留 —— Qwen-Image-Edit 原生支持这套槽位语法。
  实测 `<image1>` 与「参考图中的女孩」两种写法在本地工作流里都能生效，所以统一用
  官方槽位语法。
* **云端**：`<image1>` → 「上传的参考图」，`<image2>` → 「第二张参考图」，以此类推。
* **悬空引用**：模型写了 `<image2>` 但本次只有一张图（或一张都没有）→ 引用不存在
  序号的那**整句**被删掉，并在给用户的回执与给模型的说明里各说一声。宁可少一句，
  也不要让模型照着一张不存在的图去画。
* 写法不敏感：`< image 1 >`、`<IMAGE2>` 都认，统一收成 `<imageN>`。

### 开关与代价

`prompt_guide_enabled`（默认开）。关掉就不注入 `system_prompt`，工具说明不受影响。
注入的代价是每条相关消息多约 550 字符 —— 与它换来的「模型知道该用哪张图」相比，
这笔账是划算的；但若某个角色的人格提示词与这段规则明显打架，可以单独关。

| 5.0 flash | ✗ | 1K / 1.5K / 2K | png / jpeg | 10 张 | ✗ | ✗ |
| 5.0 pro | ✗ | 1K / 1.5K / 2K | png / jpeg | 10 张 | ✗ | ✓ |
| 5.0 | ✓ | 2K / 3K / 4K | png / jpeg | 14 张 | ✓ | ✗ |
| 5.0 lite | ✓ | 2K / 3K / 4K | png / jpeg | 14 张 | ✓ | ✗ |
| 4.5 | ✓ | 2K / 4K | 仅 jpeg | 14 张 | ✗ | ✗ |
| 4.0 | ✓ | 1K / 2K / 4K | 仅 jpeg | 14 张 | ✗ | ✓ |

配置超出模型能力时插件会**自动降级**并在结果里说明（例如 pro 配 4K → 自动改 2K），不会报错。
组图时「参考图数 + 生成数」自动收敛到官方上限 15 以内。
回退到 `fallback_model` 时同样按**新模型**的能力表重新判定尺寸 / 格式 / 组图 / 联网 / 优化模式。

### 自定义宽高（`size` 填 `WxH`）的两条官方硬约束

1. **宽高比**（宽 ÷ 高）必须落在 `[1/16, 16]`；
2. **总像素**（宽 × 高，不是宽或高单独）必须落在各模型区间内：

| 模型 | 总像素允许区间 |
| --- | --- |
| 5.0 flash | `[921600, 4624220]`（实测，与 pro 相同） |
| 5.0 pro | `[921600, 4624220]` |
| 5.0 / 5.0 lite / 4.5 | `[3686400, 16777216]` |
| 4.0 | `[921600, 16777216]` |

官方给的判定样例：`2048x1024`（209 万像素、2:1）对 pro **有效**；
`512x512`（26 万像素）**无效**；`3750x1250`（468 万像素、3:1）对 lite **有效**；
`1500x1500`（225 万像素、1:1）对 lite **无效** —— 虽然宽高比合法，但没同时满足像素下限。

插件会在本地先校验，不合规时**说明具体原因**（是宽高比还是像素）并改用 `2K`，
而不是把上游那句看不出所以然的 `parameter not valid` 直接甩给用户。

`output_format` 只在**确实需要**时才发送：`jpeg` 是接口缺省值，不传等价；
`4.0 / 4.5` 更是**压根不接受**这个参数（传了直接 400）。所以默认配置下请求体里不会有它。

另外插件带**参数自适应**，两层兜底：

1. 上游报 `InvalidParameter` 并**点名**了某个参数（如 `` `output_format` ``）→ 剔除该参数重试一次；
2. 上游报 `InvalidParameter` 但**没点名**任何参数 → 尝试剔除最可能出问题的 `output_format` 重试一次，
   并把「这个模型不收 output_format」记在内存里，之后同模型的请求直接不带（自愈）。

绝不剔除 `model` / `prompt`；参数校验失败不计费，所以这套自救不产生任何费用。

## 联网搜索与提示词优化（v1.4.0 新增）

### `web_search`：让模型先搜网再画

适合「今天北京天气画成插画」「最新款 XX 长什么样」这类**时效性**提示词。
开启后请求体里下发 `tools=[{"type":"web_search"}]`，由模型**自行判断**这次要不要真的搜
（官方说明：实际搜索次数可从响应的 `usage.tool_usage.web_search` 看出，为 0 就是没搜）。

> ⚠️ 官方文档明确：联网搜索**目前仅 Seedream 5.0 lite 支持**。
> 在其他模型上插件会自动忽略这个配置并在结果里注明，不会让请求带着一个必被拒的参数去撞 400。
> 代价是时延上升，所以默认**关闭**。

### `optimize_prompt_mode`：standard / fast

- `standard`（默认）= 质量优先。它本身就是**服务端的默认值**，所以插件根本不会下发这个字段；
- `fast` = 耗时更短、质量略降，适合对等待时间敏感的场景。

> ⚠️ 官方文档明确：`fast` 目前**仅 5.0 pro 与 4.0 支持**，`5.0 lite / 4.5` 传了会报错。
> 在这两个模型上即使配了 fast，插件也会按 standard 走并注明。

### 官方文档提到、但本版刻意没做的两项

| 参数 | 为什么不做 |
| --- | --- |
| `layer_decomposition`（图层拆分） | 仅 5.0 pro 支持，一次会吐出 1 张底图 + 最多 16 个 PNG 图层，往聊天窗里灌等于刷屏 |
| `background=transparent`（透明通道） | 仅 5.0 pro 支持，且限制很硬：必须图生图、且只收 1 张带透明通道的图；开透明还和 `output_format=jpeg` 冲突直接报错 |

两者都只在 pro 上有效，而 pro 是单价最高、且**没有免费额度**的那一档，与「用 lite 省钱」的目标相悖。
真需要的话再按需加。

- LLM 工具的结果文本不再无条件回灌提示词（它是要进对话历史的），仅在 `show_prompt=true` 时附带。
